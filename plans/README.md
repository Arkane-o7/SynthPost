# SynthPost 3D Anchor Polish Plans

Generated by the `improve` skill on 2026-08-02. These plans deliberately keep
the current CC4/Reallusion character for the first implementation pass. The
evidence says the largest quality loss occurs during material export, lighting,
and animation—not in the base mesh. Replace the character only if the quality
gate in Plan 005 proves that the repaired pipeline still misses the target.

Read each plan fully before starting, honor its STOP conditions, and update the
status row when complete. The protected legacy file
`avatar-engine/blender/avatar_template.blend` must never be overwritten.

## Dependency notes

- Plan 001 creates the fixed jobs, diagnostic report, reference frames, timing
  measurements, and scoring rubric used by every later plan.
- Plans 002 and 003 can be developed in parallel after Plan 001, but their
  candidate frames must be reviewed together because lighting changes affect
  how facial deformations read.
- Plan 004 builds on the facial layer so facial and body clips can be combined
  without fighting over the same morph targets or head bones.
- Plan 005 is a decision gate, not an automatic migration. Do not spend money
  on a new character or move the production renderer until the repaired current
  asset has been scored in the actual SynthPost compositor.

## Recommendation at planning time

Keep `synthpost_anchor_v1` through Plans 001–004. Its GLB contains a complete
CC skeleton and 152 morph targets on the main body mesh, while the neighboring
texture package contains the SSS, transmission, micro-normal, roughness, AO,
specular, and wrinkle inputs that make the Blender version look detailed. The
web GLB embeds only diffuse and normal imagery for skin, and the runtime then
reduces normal strength, adds skin-colored emissive light, disables shadows,
hides eye-occlusion geometry, and uses no image-based environment lighting.
A more expensive asset sent through the same path would lose much of its value.

## Research basis

- Three.js recommends an environment map for physical materials and provides
  PMREM/RoomEnvironment for physically based image lighting:
  <https://threejs.org/docs/pages/MeshPhysicalMaterial.html>,
  <https://threejs.org/docs/pages/PMREMGenerator.html>, and
  <https://threejs.org/docs/pages/RoomEnvironment.html>.
- Reallusion documents that its Digital Human skin depends on SSS,
  transmission, micro-normal, and masks beyond ordinary base-color/normal PBR:
  <https://manual.reallusion.com/Character-Creator-4/Content/ENU/4.0/15_Digital_Human_Shader/Skin/Texture.htm>.
- Reallusion ExpressionPlus exposes 52 ARKit shapes plus tongue shapes, and
  Apple documents using its 50+ blend-shape coefficients to drive detailed
  expressions:
  <https://manual.reallusion.com/character-creator-4/content/enu/4.0/08_Animation/Creating-Character-with-ARKit-Profile.htm>
  and <https://developer.apple.com/documentation/arkit/arfaceanchor/blendshapes>.
- Three.js supports additive clips, weighted mixing, and crossfades, which are
  the correct primitives for authored idle/gesture layers:
  <https://threejs.org/docs/pages/AnimationUtils.html>,
  <https://threejs.org/docs/pages/AnimationMixer.html>, and
  <https://threejs.org/docs/pages/AnimationAction.html>.

## Findings considered and rejected

- **Replace the current model immediately:** rejected because the current asset
  already carries a dense facial rig and the missing realism is directly tied
  to discarded textures and runtime overrides. Re-evaluate only in Plan 005.
- **Move directly to MetaHuman/Unreal:** rejected as the default because it adds
  a second rendering platform and much higher hardware/automation complexity to
  this Apple-Silicon, local-first pipeline. It remains a bake-off candidate.
- **Solve the problem only by increasing texture resolution:** rejected because
  the current 2K head maps are present; the larger issue is missing material
  channels, no skin-light transport approximation, poor eye/hair treatment, and
  mechanical animation.
- **Use more procedural sine waves for motion:** rejected because the current
  periodic blink, sway, and speech-linked hand oscillation are themselves major
  uncanny-valley signals. Seeded micro-behavior and authored clips are required.

## Audit boundary

This review covered the active CC browser renderer, its asset/job metadata,
SynthPost direction adapter, compositor anchor layer, existing output stills,
and relevant unit/type/lint gates. It did not audit TTS quality, the Studio
template UI, the old Blender 2D-face renderer, or licensed binary asset terms.
